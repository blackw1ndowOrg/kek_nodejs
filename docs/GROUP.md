# Групи (Groups API)

Документація модуля `src/modules/groups/`: створення груп, призначення кімнати й персоналу, зарахування та відрахування дітей.

---

## 1. Огляд

* **Базовий шлях:** `/api/v1/groups`. Усі ендпоінти вимагають JWT (`Authorization: Bearer <token>`).
* **Ролі:** `ADMIN` і `MANAGER` керують усіма групами; `TEACHER` лише переглядає групи, де він вихователь або помічник (через `Staff.userId`); `PARENT` доступу не має — групу своєї дитини батьки бачать через модуль `children`.
* **Зарахування дитини — лише тут.** Модуль `children` не дає змінювати `groupId`; вік дитини й ліміт місць перевіряються тільки в цьому модулі.
* **Рахуються лише активні діти.** Деактивована дитина (`isActive = false`) не займає місце в групі й не блокує її видалення.

## 2. Структура модуля

| Файл | Відповідальність |
| --- | --- |
| `groups.schema.js` | Zod-схеми: форма й типи `params`, `query`, `body` |
| `groups.repository.js` | Запити Prisma; атомарне зарахування з блокуванням рядка групи |
| `groups.service.js` | Бізнес-правила: кімната, персонал, вік, ліміти, доступ вихователя |
| `groups.controller.js` | HTTP: дані із запиту → сервіс → статус і JSON |
| `groups.routes.js` | Маршрути й порядок middleware: `auth` → `authorize` → `validate` → controller |

Сервіс отримує залежності через конструктор (`repository`, `settings`, `now`), тому тестується без бази та з фіксованою датою.

## 3. Ендпоінти

| Метод | Шлях | Ролі | Успіх | Опис |
| --- | --- | --- | --- | --- |
| GET | `/` | ADMIN, MANAGER, TEACHER | 200 `{ groups }` | Список з `childrenCount`; фільтр `?age=3` |
| GET | `/:id` | ADMIN, MANAGER, TEACHER | 200 група | Група з кімнатою, персоналом і списком активних дітей |
| POST | `/` | ADMIN, MANAGER | 201 група | Створення групи |
| PATCH | `/:id` | ADMIN, MANAGER | 200 група | Зміна назви, віку, кімнати, персоналу |
| DELETE | `/:id` | ADMIN, MANAGER | 204 | Видалення порожньої групи |
| POST | `/:id/children` | ADMIN, MANAGER | 204 | Зарахування або переведення дитини: `{ "childId": 5 }` |
| DELETE | `/:id/children/:childId` | ADMIN, MANAGER | 204 | Відрахування дитини з групи |

### 3.1. `POST /groups`

```json
{ "name": "Сонечко", "age": 3, "roomId": 6, "educatorId": 1, "assistantId": 3 }
```

| Поле | Обов'язкове | Правило |
| --- | --- | --- |
| `name` | так | рядок 1–100 символів |
| `age` | так | ціле від `MIN_AGE` до `MAX_AGE` (2–5) |
| `roomId` | так | кімната типу `GROUP`, не зайнята іншою групою чи гуртком |
| `educatorId` | ні | активний працівник типу `EDUCATOR` (або `null`), не вихователь іншої групи |
| `assistantId` | ні | активний працівник типу `ASSISTANT` (або `null`), не помічник іншої групи |

### 3.2. `PATCH /groups/:id`

Ті самі поля, усі необов'язкові. `educatorId: null` або `assistantId: null` знімає працівника з групи; кімнату зняти не можна. Порожнє тіло — 400.

## 4. Бізнес-правила

| Правило | Помилка |
| --- | --- |
| Груп не більше за `MAX_GROUPS` з налаштувань | 409 `CONFLICT` |
| Кімната існує / має тип `GROUP` / не зайнята іншою групою чи гуртком | 404 / 400 / 409 |
| Працівник існує / активний і має потрібну посаду / не працює в іншій групі | 404 / 400 / 409 |
| Вік групи з активними дітьми змінити не можна | 409 `CONFLICT` |
| Видалити можна лише групу без активних дітей (розклад видаляється каскадом) | 409 `CONFLICT` |
| Зараховується лише існуюча й активна дитина | 404 / 400 |
| Вік дитини на 1 вересня поточного навчального року дорівнює віку групи | 400 `BAD_REQUEST` |
| Активних дітей у групі не більше за `MAX_CHILDREN_IN_GROUP` | 409 `CONFLICT` |
| Дитина, що вже в цій групі, повторно не зараховується | 409 `CONFLICT` |
| Вихователь бачить лише свої групи | 404 `NOT_FOUND` |

**Переведення.** Якщо дитина вже в іншій групі, `POST /:id/children` переводить її з тими самими перевірками віку й місць.

**Ліміт 20 при одночасних запитах.** Зарахування виконується в транзакції: рядок групи блокується (`SELECT ... FOR UPDATE`), потім рахуються активні діти й оновлюється дитина. Два менеджери, які одночасно зараховують 20-ту і 21-шу дитину, виконаються по черзі, і другий отримає 409.

**Чому 404 вихователю на чужу групу.** Як і в модулі дітей: щоб перебором id не можна було з'ясувати, які групи існують.

| `tests/integration/group.test.js` | Supertest: повний HTTP-ланцюжок для всіх ролей і ендпоінтів |

Покриття `src/modules/groups/`: **100%** statements, branches, functions і lines.

```bash
npx jest tests/unit/group tests/integration/group.test.js --coverage --collectCoverageFrom='src/modules/groups/*.js'
```

Блокування `FOR UPDATE` у тестах підмінене; на справжній базі його варто перевірити вручну: два паралельні запити на зарахування в групу з 19 дітьми — один 204, другий 409.

## 6. Відкриті питання

| Питання | Поточне рішення |
| --- | --- |
| Чи потрібен ендпоінт профіту групи (виручка мінус зарплати й оренда)? | Окрема задача модуля звітів |
| Чи має менеджер переводити дитину між групами одним запитом? | Так, через `POST /:id/children` |
| Що робити з групою, коли діти переходять у наступний навчальний рік? | Поки вручну: змінити вік порожньої групи або перевести дітей |
