# Розклад та автогенерація (Schedule)

Документація модуля розкладу: автоматична генерація тижневого графіка без накладок кабінетів, перегляд, ручне редагування й очищення.

---

## 1. Огляд

- **Генерація:** `POST /schedule/generate` будує розклад Пн–Пт для **всіх** груп детермінованим алгоритмом (без `Math.random`): однаковий вхід дає однаковий розклад.
- **Гарантії генератора:** 15 занять на групу на тиждень; кожен із 5 гуртків рівно 3 рази; гурток не повторюється в один день; **жоден гурток (отже, кабінет і викладач) не стоїть у двох груп одночасно**.
- **Ручне редагування:** слот підставляється в розклад своєї групи й свого гуртка та проходить валідатор; зайнятий кабінет чи накладка дають `409`.
- **Контроль доступу (RBAC):** генерація, правка й очищення лише для `ADMIN`; розклад групи бачать усі, але кожна роль лише свої групи.
- **Чиста логіка:** шаблон дня, генератор і валідатор живуть у `src/domain/schedule/` без Express і без БД, тому тестуються без моків.
- **Помилки та валідація:** єдиний формат `{ error: { code, message, details? } }` і коди `VALIDATION_ERROR`, `UNAUTHORIZED`, `FORBIDDEN`, `NOT_FOUND`, `CONFLICT`, `BAD_REQUEST` описані в `AUTH.md`.

| Маршрут                            |    ADMIN    |   MANAGER   | TEACHER |        PARENT        |
| ---------------------------------- | :---------: | :---------: | :-----: | :------------------: |
| `POST /schedule/generate`          |     ✅      |     ❌      |   ❌    |          ❌          |
| `GET /schedule/groups/:groupId`    | ✅ будь-яка | ✅ будь-яка | ✅ свої | ✅ групи своїх дітей |
| `GET /schedule/my`                 |     ❌      |     ❌      |   ✅    |          ❌          |
| `PATCH /schedule/slots/:id`        |     ✅      |     ❌      |   ❌    |          ❌          |
| `DELETE /schedule/groups/:groupId` |     ✅      |     ❌      |   ❌    |          ❌          |

```
  schedule.schema.js       Zod-схеми: groupId, id слота, оновлення слота
```

### 2.2. Слот розкладу

Розклад зберігається в `ScheduleSlot`. Для кожної групи зберігається **весь день**: 13 слотів × 5 днів (для 4 груп це 260 рядків).

```json
{
  "id": 100,
  "groupId": 1,
  "dayOfWeek": 1,
  "startMinute": 540,
  "endMinute": 585,
  "activity": "CLUB",
  "clubId": 3,
  "club": { "id": 3, "name": "Шахи" }
}
```

| Поле                       | Значення                                                                        |
| -------------------------- | ------------------------------------------------------------------------------- |
| `dayOfWeek`                | `1` (понеділок) … `5` (п'ятниця)                                                |
| `startMinute`, `endMinute` | хвилини від півночі: `510` = 08:30, `990` = 16:30                               |
| `activity`                 | `MEAL`, `CLUB`, `WALK`, `SLEEP`, `FREE_PLAY` (у БД це звичайний рядок, не enum) |
| `clubId`, `club`           | лише для `CLUB`, в інших слотах `null`                                          |

### 2.3. Режим дня

Однаковий для всіх груп, 08:30–16:30 (`DAY_PLAN` у `template.js`).

| Час         | Хвилини | Активність           |
| ----------- | ------- | -------------------- |
| 08:30–09:00 | 510–540 | `MEAL` (сніданок)    |
| 09:00–09:45 | 540–585 | `CLUB` (заняття 1)   |
| 09:45–10:00 | 585–600 | `FREE_PLAY`          |
| 10:00–10:45 | 600–645 | `CLUB` (заняття 2)   |
| 10:45–11:00 | 645–660 | `FREE_PLAY`          |
| 11:00–12:00 | 660–720 | `WALK` (прогулянка)  |
| 12:00–12:30 | 720–750 | `MEAL` (обід)        |
| 12:30–13:00 | 750–780 | `FREE_PLAY`          |
| 13:00–14:00 | 780–840 | `SLEEP` (денний сон) |
| 14:00–14:45 | 840–885 | `CLUB` (заняття 3)   |
| 14:45–15:00 | 885–900 | `FREE_PLAY`          |
| 15:00–15:30 | 900–930 | `MEAL` (підвечірок)  |
| 15:30–16:30 | 930–990 | `FREE_PLAY`          |

### 2.4. Алгоритм генерації

Кругова ротація. Групи й гуртки сортуються за `id`; гурток для групи з індексом `g` у занятті з номером `s` (0–2) в день `d` (0–4) це:

```
clubs[ (g + d·3 + s) mod C ]        C — кількість гуртків
```

- заняття одного дня йдуть поспіль, тож при `C ≥ 3` гурток **не повторюється в день**;
- у той самий момент різні групи мають різні `g`, тож при `груп ≤ гуртків` гуртки двох груп **ніколи не збігаються**;
- при `C = 5` за 15 занять кожен гурток припадає **рівно 3 рази**.

Приклад для першої групи (за `id`) при 5 гуртках:

| День | Заняття 1  | Заняття 2  | Заняття 3  |
| ---- | ---------- | ---------- | ---------- |
| Пн   | Музика     | Англійська | Шахи       |
| Вт   | Малювання  | Танці      | Музика     |
| Ср   | Англійська | Шахи       | Малювання  |
| Чт   | Танці      | Музика     | Англійська |
| Пт   | Шахи       | Малювання  | Танці      |

Для другої групи значення зсунуті на один гурток і так далі. (Назви відповідають порядку створення гуртків у seed; насправді береться порядок за `id`.)

**Обмеження ємності** (`ScheduleCapacityError` → `422`):

- гуртків менше за 3;
- груп більше, ніж гуртків.

Якщо груп немає, розклад порожній.

### 2.5. Валідатор

`validateSchedule(slots)` повертає список конфліктів; порожній список означає коректний розклад. Порівнюються **інтервали**, а не лише однаковий початок, бо унікальні індекси БД ловлять тільки збіг `startMinute`. Слоти, що лише торкаються межами, конфліктом не є.

| Тип                    | Що означає                                             |
| ---------------------- | ------------------------------------------------------ |
| `GROUP_OVERLAP`        | у групи два слоти перетинаються в часі                 |
| `CLUB_DOUBLE_BOOKED`   | один гурток (кабінет і викладач) в двох груп одночасно |
| `CLUB_REPEATED_IN_DAY` | той самий гурток двічі за день в однієї групи          |
| `LESSON_OUT_OF_WINDOW` | заняття поза періодами 09:00–12:00 / 14:00–17:45       |
| `MAX_LESSONS_PER_DAY`  | у групи більше 3 занять на день                        |
| `OUT_OF_HOURS`         | слот поза межами дня                                   |
| `INVALID_TIME`         | кінець не пізніше за початок                           |

Кабінет і гурток прив'язані один до одного, тож перевірка зайнятості кабінету дорівнює `CLUB_DOUBLE_BOOKED`.

### 2.6. Хто які групи бачить

Фільтр доступу будується в репозиторії за роллю користувача:

| Роль               | Умова                                 |
| ------------------ | ------------------------------------- |
| `ADMIN`, `MANAGER` | без обмежень                          |
| `TEACHER`          | він вихователь **або помічник** групи |
| `PARENT`           | у групі є його дитина                 |

Недоступна або неіснуюча група дає `404`, а не `403`.

## 3. Ендпоінти API

Усі маршрути підключені за префіксом `/api/v1/schedule` і вимагають `Authorization: Bearer <TOKEN>`.

### 3.1. Генерація розкладу

- **URL:** `POST /api/v1/schedule/generate`
- **Доступ:** `ADMIN`
- **Тіло запиту:** немає
- **Дія:** в одній транзакції видаляє **всі** наявні слоти (разом із ручними правками) і створює нові.
- **Успішна відповідь (`201 Created`):**
  ```json
  { "groups": 4, "clubs": 5, "slots": 260 }
  ```
- **Нестача гуртків (`422`):** тіло в стандартному форматі помилки, наприклад:
  ```json
  { "error": { "message": "Груп (6) більше, ніж гуртків (5): кабінети неминуче перетнуться" } }
  ```

### 3.2. Розклад групи

- **URL:** `GET /api/v1/schedule/groups/:groupId`
- **Доступ:** `ADMIN`, `MANAGER`, `TEACHER` (свої групи), `PARENT` (групи своїх дітей)
- **Успішна відповідь (`200 OK`):** слоти за днем і часом
  ```json
  {
    "group": { "id": 1, "name": "Сонечко", "age": 2 },
    "slots": [
      {
        "id": 1,
        "groupId": 1,
        "dayOfWeek": 1,
        "startMinute": 510,
        "endMinute": 540,
        "activity": "MEAL",
        "clubId": null,
        "club": null
      }
    ]
  }
  ```
  Якщо розклад ще не згенеровано, `slots` порожній.
- **Помилки:** `400 VALIDATION_ERROR` (некоректний `groupId`), `404 NOT_FOUND` (групи немає або вона недоступна)

### 3.3. Мої заняття

- **URL:** `GET /api/v1/schedule/my`
- **Доступ:** `TEACHER`
- **Що повертає:** слоти, де гурток веде цей користувач (для викладача гуртка лише його заняття) або де він вихователь чи помічник групи (увесь день групи).
- **Успішна відповідь (`200 OK`):** кожен слот містить ще й групу
  ```json
  {
    "slots": [
      {
        "id": 100,
        "groupId": 1,
        "dayOfWeek": 1,
        "startMinute": 540,
        "endMinute": 585,
        "activity": "CLUB",
        "clubId": 3,
        "club": { "id": 3, "name": "Шахи" },
        "group": { "id": 1, "name": "Сонечко" }
      }
    ]
  }
  ```
- **Порожній `slots`**, якщо працівник не прив'язаний до акаунта (`Staff.userId`), не веде гурток або розклад не згенеровано чи не перегенеровано після появи гуртка.

### 3.4. Ручне редагування слота

- **URL:** `PATCH /api/v1/schedule/slots/:id`
- **Доступ:** `ADMIN`
- **Тіло запиту:** хоча б одне поле

  ```json
  { "activity": "CLUB", "clubId": 2 }
  ```

  | Поле          | Правило                                                                                        |
  | ------------- | ---------------------------------------------------------------------------------------------- |
  | `dayOfWeek`   | ціле 1–5                                                                                       |
  | `startMinute` | ціле 0–1439                                                                                    |
  | `endMinute`   | ціле 1–1440                                                                                    |
  | `activity`    | `FREE_PLAY` або `CLUB`                                                                         |
  | `clubId`      | ціле > 0 (обов'язковий при `FREE_PLAY` → `CLUB`; при `CLUB` → `FREE_PLAY` скидається в `null`) |
  - Дозволено змінювати активність: `FREE_PLAY` → `CLUB` (у слотах зон занять 09:00–12:00 та 14:00–17:45; `clubId` обов'язковий) та `CLUB` → `FREE_PLAY` (`clubId` автоматично скидається в `null`).
  - Заняття дозволені лише в слотах зон занять (межі беруться з констант генератора). Спроба призначити заняття на сон, їжу або поза зонами занять повертає `400 BAD_REQUEST`.
  - Знімати заняття (`CLUB` → `FREE_PLAY`) можна завжди.
  - Якщо вказано `startMinute` і `endMinute`, початок має бути раніше за кінець.

- **Успішна відповідь (`200 OK`):** оновлений слот із `club`
- **Помилки:**

  | Статус | Код                | Коли                                                                                          |
  | ------ | ------------------ | --------------------------------------------------------------------------------------------- |
  | `400`  | `VALIDATION_ERROR` | невалідне тіло                                                                                |
  | `400`  | `BAD_REQUEST`      | спроба призначити заняття на сон/їжу/поза зонами; `clubId` для не-CLUB; некоректна активність |
  | `404`  | `NOT_FOUND`        | слота або гуртка немає                                                                        |
  | `409`  | `CONFLICT`         | порушення розкладу: `CLUB_DOUBLE_BOOKED`, `CLUB_REPEATED_IN_DAY`, `MAX_LESSONS_PER_DAY` тощо  |

  Блокують правку лише конфлікти, у яких бере участь **цей слот**; чужі існуючі проблеми їй не заважають. У повідомленні перелічені типи конфліктів:

  ```json
  { "error": { "code": "CONFLICT", "message": "Конфлікт розкладу: CLUB_DOUBLE_BOOKED" } }
  ```

### 3.5. Очищення розкладу групи

- **URL:** `DELETE /api/v1/schedule/groups/:groupId`
- **Доступ:** `ADMIN`
- **Успішна відповідь:** `204 No Content`. Видаляє всі слоти групи, саму групу не чіпає.
- **Помилки:** `400 VALIDATION_ERROR`, `404 NOT_FOUND`

## 4. Швидка перевірка через cURL

```bash
BASE=http://localhost:3000/api/v1
login() { curl -s -X POST $BASE/auth/login -H "Content-Type: application/json" \
  -d "{\"email\":\"$1\",\"password\":\"$2\"}" | jq -r '.token'; }

# 1. Адмін генерує розклад:
ADMIN=$(login admin@kindergarten.local 'Admin123!')
curl -s -X POST -H "Authorization: Bearer $ADMIN" $BASE/schedule/generate

# 2. Розклад групи 1 (очікується 65 слотів):
curl -s -H "Authorization: Bearer $ADMIN" $BASE/schedule/groups/1 | jq '.slots | length'

# 3. Ручна правка слота (id слота візьміть з відповіді попереднього кроку):
curl -s -X PATCH $BASE/schedule/slots/<SLOT_ID> \
  -H "Authorization: Bearer $ADMIN" -H "Content-Type: application/json" \
  -d '{"startMinute":600,"endMinute":645}'

# 4. Мої заняття викладача гуртка (очікується 12 слотів для 4 груп):
TEACHER=$(login teacher.music@kindergarten.local 'Password123!')
curl -s -H "Authorization: Bearer $TEACHER" $BASE/schedule/my | jq '.slots | length'
```

Паролі тут це значення за замовчуванням із `seed.js`; якщо в `.env` задані `ADMIN_PASSWORD` чи `SEED_USER_PASSWORD`, підставте свої.

## 5. Початкові дані (seed)

`seedSchedule()` у `prisma/seed.js` викликає `generateSchedule` для **всіх** груп: у транзакції видаляє всі слоти й створює нові. Повторний `npm run db:seed` перезаписує розклад, тож ручні правки при цьому втрачаються.

## 7. Обмеження v1

- **Правка слота не атомарна:** читання, перевірка й запис ідуть окремими запитами. Два адміни одночасно можуть поставити перетинні заняття зі зсувом початку, бо БД ловить лише точний збіг `startMinute`.
- **Правка не стежить за повтором гуртка:** адмін може поставити гурток, який у групи вже є цього дня, або порушити «рівно 3 рази на тиждень».
- **Батько бачить групу, де його дитина неактивна** (`isActive` у фільтрі не враховано).
- У `409` лише типи конфліктів, без переліку слотів.
- `activity` це коди (`CLUB`, `MEAL`…), а не українські назви; відображення назв справа клієнта.
- Розподіл «рівно по 3 рази» гарантований лише при 5 гуртках; в інших випадках розподіл приблизно рівномірний.
