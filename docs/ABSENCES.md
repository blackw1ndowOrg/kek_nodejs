# Відсутності (Absences API)

Документація модуля `src/modules/absences/` і правил у `src/domain/absence.js`: батьки повідомляють, що дитина не прийде, а billing не нараховує харчування за цей день.

---

## 1. Огляд

- **Правило з README:** якщо батьки попередили про відсутність **до 08:30** дня відсутності, оплата за харчування за цей день не нараховується.
- **Базовий шлях:** `/api/v1/children/:childId/absences`. Усі ендпоінти вимагають JWT.
- **Ролі:** `PARENT` — лише своя дитина (чужа → 404, як і неіснуюча); `ADMIN`, `MANAGER` — будь-яка дитина; `TEACHER` → 403.
- **Час — за Києвом** (`Europe/Kyiv`). Сервер може працювати в UTC, тому 08:30 рахується з урахуванням поясу: це 06:30 UTC узимку і 05:30 UTC улітку.
- **`notifiedAt` ставить сервер** (момент запиту). Клієнт його не передає: тіло з `notifiedAt` → 400.

---

## 2. Модель

```prisma
model Absence {
  id         Int      @id @default(autoincrement())
  childId    Int
  date       DateTime @db.Date
  notifiedAt DateTime

  child Child @relation(fields: [childId], references: [id], onDelete: Cascade)

  @@unique([childId, date])
}
```

| Поле                        | Зміст                                           |
| --------------------------- | ----------------------------------------------- |
| `date`                      | День відсутності (`YYYY-MM-DD`)                 |
| `notifiedAt`                | Коли батьки повідомили                          |
| `@@unique([childId, date])` | Одна відсутність на дитину на день; дубль → 409 |
| `onDelete: Cascade`         | Відсутності видаляються разом із дитиною        |

Міграція: `prisma/migrations/20261109140000_add_absence`.

`counted` у базі не зберігається, а обчислюється: `notifiedAt < 08:30 (Київ) дня date`.

## 4. Ендпоінти

| Метод  | Шлях              | Успіх                                           | Опис                                                           |
| ------ | ----------------- | ----------------------------------------------- | -------------------------------------------------------------- |
| POST   | `/`               | 201 відсутність                                 | Повідомити про відсутність: `{ "date": "2026-11-12" }`         |
| GET    | `/?month=YYYY-MM` | 200 `{ childId, month, countedDays, absences }` | Відсутності за місяць; без `month` — поточний місяць за Києвом |
| DELETE | `/:absenceId`     | 204                                             | Скасувати відсутність                                          |

Відповідь для однієї відсутності:

```json
{
  "id": 7,
  "childId": 1,
  "date": "2026-11-12",
  "notifiedAt": "2026-11-11T18:20:00.000Z",
  "counted": true
}
```

Даних дитини (знижки, кумівства) у відповідях немає.

## 5. Бізнес-правила

| Правило                                                                                             | Помилка                |
| --------------------------------------------------------------------------------------------------- | ---------------------- |
| Дитина існує; для батьків — це їхня дитина                                                          | 404 `NOT_FOUND`        |
| Дитина активна (не вибула)                                                                          | 400 `BAD_REQUEST`      |
| `date` — не субота й не неділя                                                                      | 400 `BAD_REQUEST`      |
| `date` не раніше за сьогодні (за Києвом). Сьогодні можна: після 08:30 запис буде з `counted: false` | 400 `BAD_REQUEST`      |
| Одна відсутність на дату (`@@unique`, паралельні запити теж)                                        | 409 `CONFLICT`         |
| `month` у форматі `YYYY-MM`                                                                         | 400 `VALIDATION_ERROR` |
| Скасувати можна лише до 08:30 дня відсутності                                                       | 409 `CONFLICT`         |
| Скасовується лише відсутність цієї дитини                                                           | 404 `NOT_FOUND`        |

**Межа 08:30.** 08:29:59 → `counted: true`; 08:30:00 → `counted: false`.

**Скасування після 08:30** заборонене: на цей момент харчування на день уже заплановане. Це рішення чекає підтвердження BA; якщо BA дозволить, змінюється одна перевірка в `remove`.

## 6. Вплив на billing

`GET /api/v1/billing/children/:childId?month=YYYY-MM` (без `month` — поточний місяць за Києвом):

- днів харчування = `21 − зараховані відсутності місяця`, не менше 0;
- `monthly.meals` = ставка за віком групи × днів харчування;
- у `monthly` додано `month`, `mealDays`, `absentDays`; `amountDue` для місячного плану зменшується разом із `monthly.total`;
- навчання (`monthly.tuition`) не змінюється: 15 000 грн незалежно від відвідуваності.

Приклад, група 3-річних (ставка 400 грн/день):

| Відсутності за жовтень | `mealDays` | `monthly.meals` |
| ---------------------- | ---------- | --------------- |
| немає                  | 21         | 8 400 грн       |
| 2 зараховані           | 19         | 7 600 грн       |
| 1, повідомили о 08:30  | 21         | 8 400 грн       |

**Річна сума (`yearly`) відсутностей не враховує**: за рік наперед вони невідомі, тож рахується за 21 день кожного місяця.

**Оплата** (`POST /billing/children/:childId/payments`) не змінювалась: сума платежу — це авансова сума без відсутностей.

**Аналітика не змінювалась:** прогноз харчування рахується як ставка × 21 × 0,8 — коефіцієнт відвідуваності лишається заглушкою за вимогою.
